# 楔子：一个写代码的人，为什么要想这些问题？

之前我写了一套关于汽车电子软件的开源技术书，总共七本：[《从沙子到车辙》（总纲）](https://github.com/Lularible/from-sand-to-ruts)、[《PTP时间同步》](https://github.com/Lularible/ptp-book)、[《HSM安全模块》](https://github.com/Lularible/hsm-book)、[《Flash存储技术》](https://github.com/Lularible/storage-book)、[《UDS诊断协议》](https://github.com/Lularible/uds-book)、[《功能安全》](https://github.com/Lularible/safety-book-iso26262)、[《软件工程》](https://github.com/Lularible/swe-book)。从芯片怎么从沙子里造出来，一路写到软件工程。

我在[《从沙子到车辙》](https://github.com/Lularible/from-sand-to-ruts)的序言里写过那七本书的来由：这个想法可以追溯到上大学的时候，室友在写C代码，我在旁边看着，突然想，“如果能够知道代码运行时，电脑里面是如何控制电子的就好了。”

我在那本书里也问了一个问题：**这套系统究竟有多深？**从应用层往下追，经过框架、驱动、内核、固件，一路追到晶体管的开关动作，再往下就没有了，电子就是最小单元了。我站在那个地方，发现我对电子在做什么一无所知。我写了那本书，依然无法完全知道软件运行时电子究竟在做什么，但至少我对这套系统懂了一点点。

原本以为这样就够了，后来发现不够。因为如果继续往下想，会碰到另一个问题。前面问的是“电子在做什么”，再往下，问题变成了**我在做什么**。

## 0.1 深夜的bug，和“这一切为了什么”

我想先请你看一个场景。它可能就发生在你身上。

深夜，屏幕的亮度已经调暗了，光标在最后一行的末尾闪烁，窗外的城市也暗了大部分。你不知道现在是几点。你刚改完一个bug，一条忘记加的边界检查。但就是这条边界检查，会让设备陷入未定义状态。你加上了，编译，烧录，测试通过。

你不会因为修了这条边界检查而升职，不会有客户写感谢信给你，甚至不会有人知道你修过它。但你知道，明天设备跑到那个分支时，不会再崩溃了。

你盯着屏幕，光标还在闪。

你突然想问自己一个问题：**这一切到底是为了什么？**

说为了钱，你见过月薪比你高两倍的人，他们跟你一样在加班，一样在改bug，一样在半夜回oncall。说为了名，你的名字不会出现在任何一台量产设备的铭牌上。说为了“改变世界”，你调的CAN总线波特率改变不了世界。那你为什么还在做？

技术书能告诉你系统怎么工作，但回答不了你为什么要让它工作。

## 0.2 从“电子在做什么”到“我在做什么”

有人问过我另一个问题：你一个写代码的，为什么要花时间去想这些底层的东西？

因为把底层的东西一层层想透，最后一定会撞上这个问题：我做这些，究竟是为了什么。它和技术无关。这就是这本书要讨论的问题。它不讲技术，不教怎么写代码、怎么配置AUTOSAR模块、怎么调PTP时间同步。我写过的那七本书，回答的是另一个问题：**这套系统是怎么工作的？**

这本书要问的是：**在注定失败的前提下，人为什么还要做？**

失败是预设，在你动手之前就已经成立。你写的代码终将过时，你维护的模块终将被重写，你调试过的那颗芯片终将停产。这是技术的迭代。比技术迭代更彻底的，是物理法则：承载这一切的物质，最终都会被熵增抹平。

后面七章，就沿着这条线往下走。第一章讲熵增，第二章讲人，第三章讲技术，第四章讲为什么推，第五章讲凭什么推，第六章看AI，第七章回到你自己。一层一层往下压，最后压到最底下的那个“我”。

## 0.3 三本书，同一个问题

那套丛书里的每一本，写到最后，我都停在同一个问题面前。

写存储那本的时候，我讲了一件印加人的旧事：他们用一根根打了结的绳子记录人口、税收和历史。几万条奇普，至今没有被完整破译。他们已经消失了，他们留下的很多信息，我们也读不到了。

写时间同步那本的时候，我拆解了IEEE 1588标准，分析了LinuxPTP的9种端口状态，实现了一个可运行的ptp-lite。我对自己的要求是每一行代码都要能跑，每一个结论都要有出处。写完之后我问自己：**二十年以后还有人用PTP吗？**可能不多了。一百年以后呢？绝对没人用了。那为什么要写？

写安全那本的时候，我从岩画和密码讲起，经过凯撒密码、恩尼格玛机，一直讲到PKCS#11 v3.1标准和SoftHSM2源码。我在想，人类花了几千年加密、解密、再加密，最后我们发现数学是最好的锁。但锁总会被打开，信息总会被泄露。那为什么还要锁？

这三本书，三个完全不同的领域，最后都落在同一个问题上：一件事注定会消失，为什么还要做？

## 0.4 推石头

这些问题，就藏在每一行代码的背后。我做了一件事，我知道这件事终将消失，我还是做了。

这就是推石头。

西西弗斯被众神惩罚，永远把一块巨石推上山顶。每次快到山顶，石头滚下来。他走下山，重新推，再滚下来，再推，无穷无尽。加缪说，**我们必须想象西西弗斯是幸福的**。我以前觉得这句话是鸡汤，现在我觉得它是一句工程描述。

你知道石头会滚下来，你知道代码会过时，你知道芯片会停产，你知道自己做过的所有事最终都会被熵增抹平。

我以前把这件事读成悲壮。悲壮里还留着一点希望：石头有一天也许能停在山顶。加缪不要这个希望。石头停不停在山顶，和推石头的人无关。推石头这件事，本身就是目的。

所以你还是会推。理由很朴素：推石头的过程，就是存在本身。

## 0.5 这本书写给谁

这本书给不出标准答案，只能陪你把这个问题的每一层都走一遍。如果你也有过这样的深夜：设备终于跑通，窗外已经泛白，你却开始想上面那些问题，这本书就是为你写的。

如果你还没有过这种时刻，也许这本书会让你在某个深夜突然想起来。

不需要懂PTP，不需要写过AUTOSAR，不需要调过Flash驱动。只需要做过一件事：在知道它可能毫无意义的前提下，仍然认真地做完了它。先做，意义是做完之后才长出来的。
